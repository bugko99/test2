# Dashboard, Report & Notification Design: ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ (DCMS)
(Project Name: BUGKOShop)

เอกสารฉบับนี้กำหนดรูปแบบการแสดงผลหน้า Dashboard, การดึงรายงาน (Report), และเงื่อนไขการแจ้งเตือน (Notification & SLA Alerts) เพื่อตอบสนองความต้องการของผู้บริหารและเพิ่มประสิทธิภาพการทำงานของเจ้าหน้าที่

## 1. การออกแบบ Dashboard
Dashboard ต้องตอบคำถามเชิงวิเคราะห์ให้ผู้บริหารและหัวหน้าศูนย์ดำรงธรรมได้ทันที โดยแบ่งองค์ประกอบบนหน้าจอ (UI Components) ออกเป็นดังนี้:

### 1.1 ตัวกรองข้อมูล (Filters)
- **ช่วงเวลา (Date Range):** เลือกดูข้อมูล วันนี้, สัปดาห์นี้, เดือนนี้, ปีนี้ หรือกำหนดวันที่เองได้
- **หน่วยงาน (Agency):** เลือกดูเฉพาะเรื่องของหน่วยงานใดหน่วยงานหนึ่ง (สำหรับผู้ว่าฯ หรือหัวหน้าศูนย์)
- **หมวดหมู่ (Category):** กรองตามประเภทเรื่องร้องเรียน
- **พื้นที่ (Location/District):** กรองตามอำเภอที่เกิดเหตุ

### 1.2 Dashboard Cards (สรุปตัวเลขบรรทัดแรก)
- **Card 1: เรื่องร้องเรียนสะสมทั้งหมด (Total Complaints)** - จำนวนเรื่องร้องเรียนทั้งหมดในช่วงเวลาที่เลือก
- **Card 2: เรื่องรับใหม่วันนี้ (New Today)** - นับเฉพาะเรื่องที่มีสถานะ `NEW` ในวันที่ปัจจุบัน
- **Card 3: อยู่ระหว่างดำเนินการ (In Progress)** - รวมเรื่องที่อยู่ในสถานะ `ASSIGNED`, `IN_PROGRESS`, และ `PENDING_INFO`
- **Card 4: แก้ไขแล้ว / ยุติเรื่อง (Resolved/Closed)** - รวมเรื่องที่มีสถานะ `RESOLVED` และ `CLOSED`
- **Card 5: เรื่องเกินกำหนด (Overdue/SLA Breach) 🔴** - จำนวนเรื่องที่ `sla_due_date` ผ่านไปแล้วแต่สถานะยังไม่ใช่ `RESOLVED` หรือ `CLOSED`

### 1.3 กราฟสถิติ (Charts)
- **กราฟแท่งแนวนอน (Horizontal Bar Chart) ➔ "หน่วยงานใดมีเรื่องค้างมากที่สุด"**
  - แกน Y: ชื่อหน่วยงาน
  - แกน X: จำนวนเรื่องร้องเรียนที่ค้างอยู่ (สถานะไม่ใช่ CLOSED/REJECTED)
- **กราฟพาย / โดนัท (Pie/Doughnut Chart) ➔ "ประเภทเรื่องใดพบมากที่สุด"**
  - แสดงสัดส่วน (%) ของเรื่องร้องเรียนแยกตาม Category
- **กราฟแท่งแนวตั้ง (Vertical Bar Chart) ➔ "พื้นที่ใดมีเรื่องร้องเรียนมากที่สุด"**
  - แกน Y: จำนวนเรื่องร้องเรียน
  - แกน X: ชื่ออำเภอ
- **กราฟเส้น (Line Chart) ➔ "แนวโน้มรายเดือนเป็นอย่างไร"**
  - แกน Y: จำนวนเรื่องร้องเรียน
  - แกน X: เดือน (ม.ค. - ธ.ค.)
  - แสดงเส้นเปรียบเทียบเรื่องรับเข้า (เส้นสีน้ำเงิน) เทียบกับเรื่องที่ทำเสร็จ (เส้นสีเขียว)

## 2. การออกแบบรายงาน (Report & Export)
ระบบต้องสามารถส่งออกข้อมูลเป็นไฟล์ **Excel (.xlsx)** หรือ **CSV** ได้ โดยมีมุมมองของตาราง (Tables) ดังนี้:

### 2.1 ตารางรายงานสรุปรายเรื่อง (Detailed Case Report)
- **คอลัมน์:** เลขที่รับเรื่อง, วันที่รับเรื่อง, หัวข้อ, หมวดหมู่, ชื่อผู้ร้อง, อำเภอ, หน่วยงานรับผิดชอบ, สถานะปัจจุบัน, วันที่ครบกำหนด SLA, จำนวนวันที่เกินกำหนด (หากมี)
- **วัตถุประสงค์:** เพื่อให้เจ้าหน้าที่นำไปปริ้นท์หรือสรุปยอดรายวัน/สัปดาห์

### 2.2 ตารางรายงานประสิทธิภาพหน่วยงาน (Agency Performance Report)
- **คอลัมน์:** ชื่อหน่วยงาน, จำนวนเรื่องรับทั้งหมด, เรื่องยุติแล้ว, เรื่องที่กำลังทำ, เรื่องเกินกำหนด (SLA Breach), เปอร์เซ็นต์การปิดเรื่อง (Resolution Rate %)
- **วัตถุประสงค์:** ผู้บริหารใช้ประเมินผลการทำงานของหน่วยงานระดับจังหวัด

## 3. เงื่อนไขการแจ้งเตือน (Notification Rules)
การแจ้งเตือนจะแสดงบนไอคอนกระดิ่ง (In-app Notification) บนมุมขวาบนของระบบ

| เหตุการณ์ (Event Trigger) | ผู้รับการแจ้งเตือน (Recipient) | ข้อความแจ้งเตือน (ตัวอย่าง) |
|---|---|---|
| **มีเรื่องร้องเรียนเข้าใหม่** | เจ้าหน้าที่ศูนย์ดำรงธรรม | "มีเรื่องร้องเรียนเข้าใหม่: [หัวข้อเรื่อง] กรุณาตรวจสอบ" |
| **ศูนย์ดำรงธรรมมอบหมายงาน** | หน่วยงานที่รับผิดชอบ | "ท่านได้รับมอบหมายงานใหม่: [หัวข้อเรื่อง] กรุณากดรับเรื่อง" |
| **หน่วยงานขอข้อมูลเพิ่มเติม** | เจ้าหน้าที่ศูนย์ดำรงธรรม | "[ชื่อหน่วยงาน] ต้องการข้อมูลเพิ่มเติมสำหรับเรื่อง: [หัวข้อเรื่อง]" |
| **หน่วยงานแก้ไขปัญหาเสร็จสิ้น** | เจ้าหน้าที่ศูนย์ดำรงธรรม | "[ชื่อหน่วยงาน] รายงานผลการแก้ไขปัญหาเรื่อง: [หัวข้อเรื่อง] กรุณาตรวจสอบและยุติเรื่อง" |
| **ศูนย์ดำรงธรรมตีกลับให้แก้ไขใหม่** | หน่วยงานที่รับผิดชอบ | "ผลการปฏิบัติงานของเรื่อง [หัวข้อเรื่อง] ถูกตีกลับ กรุณาดำเนินการเพิ่มเติม" |

## 4. กฎการแจ้งเตือน SLA ขีดเส้นตาย (SLA Alert Rules)
เพื่อป้องกันเรื่องร้องเรียนล่าช้า ระบบจะมีกลไกตรวจสอบและแจ้งเตือนตามระยะเวลาที่กำหนด (SLA) ดังนี้:

**ตัวแปรสำคัญ:** 
- `SLA_DAYS` = เวลาดำเนินการตามมาตรฐานของหมวดหมู่นั้น (เช่น 15 วัน)
- `START_DATE` = วันที่ศูนย์ดำรงธรรมกดมอบหมายงาน (`ASSIGNED`)
- `DUE_DATE` = `START_DATE` + `SLA_DAYS`

**กฎการแจ้งเตือน (Alert Logic):**
1. **การแจ้งเตือนล่วงหน้า (Warning Alert):**
   - **เงื่อนไข:** วันที่ปัจจุบัน (Today) เหลือเวลาอีก 3 วันจะถึง `DUE_DATE`
   - **Action:** ระบบส่ง Notification ไปยัง **หน่วยงานที่รับผิดชอบ** ("เรื่อง [หัวข้อ] จะครบกำหนดในอีก 3 วัน")
   - **สถานะ:** แสดงป้ายสีเหลือง (Warning) ในหน้ารายการของเจ้าหน้าที่
2. **การแจ้งเตือนเมื่อเกินกำหนด (Overdue Alert):**
   - **เงื่อนไข:** วันที่ปัจจุบัน (Today) เกิน `DUE_DATE` และสถานะยังไม่ใช่ RESOLVED หรือ CLOSED
   - **Action:** 
     1. ระบบส่ง Notification แบบระดับสูง (High Priority) ไปยัง **หน่วยงานนั้น** และ **ศูนย์ดำรงธรรม**
     2. แสดงป้ายสีแดง (Overdue) หราใน Dashboard Card 5
     3. (ทางเลือก) ส่งแจ้งเตือนรายงานสรุปรายวันไปยัง **ผู้บริหารจังหวัด** ว่ามีหน่วยงานใดบ้างที่ทำเรื่องเกินกำหนด

*(หมายเหตุ: ระบบอาจต้องมี Background Job หรือ Cron Job รันทุกๆ เที่ยงคืน เพื่อตรวจสอบวันที่ปัจจุบันเทียบกับ `sla_due_date` และยิงการแจ้งเตือนเหล่านี้)*
