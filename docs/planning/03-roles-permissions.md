# Roles & Permissions: ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ (DCMS)
(Project Name: BUGKOShop)

เอกสารฉบับนี้กำหนดบทบาท (Roles) และสิทธิ์การเข้าถึงข้อมูล (Permissions) ของผู้ใช้งานในระบบ เพื่อให้การทำงานเป็นไปตามสายการบังคับบัญชา และรักษาความปลอดภัยของข้อมูลส่วนบุคคล (PDPA)

## 1. ตารางสรุปบทบาทและสิทธิ์ (Roles and Permissions Table)

| Role | คำอธิบายบทบาท | สิทธิ์ที่ทำได้ (Actions) | หน้าจอที่เข้าถึงได้ (Accessible Pages) | ข้อมูลที่มองเห็นได้ (Visible Data) | ข้อจำกัดของ Role |
|---|---|---|---|---|---|
| **1. Super Admin** | ผู้ดูแลระบบและโครงสร้างพื้นฐานทางเทคนิค | - เพิ่ม/ลบ/แก้ไขข้อมูลผู้ใช้งานทั้งหมด<br>- จัดการ Master Data (เช่น เพิ่มหน่วยงานใหม่, ตั้งค่าหมวดหมู่)<br>- รีเซ็ตรหัสผ่าน | - จัดการผู้ใช้งาน (User Management)<br>- ตั้งค่าระบบ (System Settings)<br>- System Logs | - ข้อมูล User ทั้งหมดในระบบ<br>- System Configuration<br>- *อาจมองเห็นเรื่องร้องเรียนเพื่อแก้ปัญหาทางเทคนิค แต่ไม่มีหน้าที่เข้าไปก้าวก่ายงาน* | - ไม่ควรมีหน้าที่ในการรับเรื่อง ส่งต่อ หรือยุติเรื่องร้องเรียนด้วยตนเอง |
| **2. เจ้าหน้าที่ศูนย์ดำรงธรรม** | ผู้ปฏิบัติงานด่านหน้า รับเรื่อง คัดกรอง และส่งต่อ (Operator) | - บันทึกเรื่องร้องเรียนใหม่<br>- แนบไฟล์หลักฐาน<br>- มอบหมายเรื่องให้หน่วยงาน (Assign)<br>- ปรับสถานะและ "ยุติเรื่อง" (Close Case) | - หน้ารายการเรื่องร้องเรียนทั้งหมด<br>- หน้าบันทึกเรื่องร้องเรียน<br>- หน้ารายละเอียดเรื่อง | - ข้อมูลเรื่องร้องเรียนทั้งหมด<br>- ข้อมูลผู้ร้องเรียนทั้งหมด<br>- ประวัติการอัปเดตสถานะของทุกเรื่อง | - ไม่สามารถเพิ่ม/ลบผู้ใช้งาน (User) ในระบบได้ ต้องให้ Admin ทำให้ |
| **3. หัวหน้าศูนย์ดำรงธรรม** | ผู้ควบคุมดูแลการทำงานของเจ้าหน้าที่ศูนย์ดำรงธรรมและภาพรวม | - มีสิทธิ์ทุกอย่างเหมือน "เจ้าหน้าที่ศูนย์ดำรงธรรม"<br>- ดูรายงาน Dashboard เชิงลึก<br>- อนุมัติการขยายเวลา SLA | - หน้าจอทั้งหมดของเจ้าหน้าที่<br>- หน้า Dashboard (ผู้บริหารระดับต้น)<br>- รายงานสถิติ | - ข้อมูลเรื่องร้องเรียนทั้งหมด<br>- ข้อมูลประสิทธิภาพการทำงานของเจ้าหน้าที่ภายในทีม | - ไม่สามารถแก้ไขการตั้งค่าระดับโครงสร้าง (System Settings) ได้ |
| **4. หน่วยงานที่รับผิดชอบ** | เจ้าหน้าที่ของส่วนราชการ/หน่วยงานภายนอกที่ได้รับมอบหมายเรื่องให้ไปแก้ไขปัญหา | - รับเรื่อง (Acknowledge)<br>- อัปเดตสถานะ (กำลังดำเนินการ, แก้ไขแล้ว)<br>- พิมพ์รายงานผล/แนบไฟล์ตอบกลับ | - หน้ารายการเรื่องร้องเรียน (เฉพาะของตน)<br>- หน้ารายละเอียดเรื่อง | - **เฉพาะเรื่องร้องเรียนที่ถูกมอบหมายให้หน่วยงานของตนเท่านั้น**<br>- ข้อมูลผู้ร้องเรียน (เท่าที่จำเป็น) | - ไม่สามารถรับเรื่องร้องเรียนใหม่เข้าระบบเองได้<br>- มองไม่เห็นเรื่องร้องเรียนของหน่วยงานอื่น<br>- **ไม่สามารถปิดเรื่อง (Close Case) ขั้นสุดท้ายได้** ทำได้แค่ "รายงานว่าแก้ไขแล้ว" |
| **5. ผู้บริหารจังหวัด** | (เช่น ผู้ว่าราชการ, รองผู้ว่าฯ) ผู้ต้องการดูภาพรวมเพื่อสั่งการ | - เข้าถึง Dashboard เท่านั้น<br>- Export รายงานสถิติภาพรวม | - หน้า Dashboard<br>- หน้ารายงานสถิติ (Reports) | - กราฟ, สถิติภาพรวม, สรุปสถานะ<br>- จำนวนเรื่องค้างของแต่ละหน่วยงาน | - **ไม่มีสิทธิ์ (Read-only)** ในการแก้ไข, ลบ, เปลี่ยนสถานะ, หรือเข้ายุ่งเกี่ยวกับเรื่องร้องเรียนในระดับปฏิบัติการ |
| **6. ประชาชนผู้ร้องเรียน** | ผู้ใช้งานจากภายนอกที่ต้องการติดตามสถานะเรื่องของตนเอง | - ค้นหาสถานะเรื่องร้องเรียนจากเลข Tracking Number | - หน้าติดตามสถานะ (Tracking Page แบบ Public) | - สถานะปัจจุบันของเรื่องตัวเอง<br>- ประวัติการเคลื่อนไหวสั้นๆ (ไม่มีข้อมูลภายใน) | - ไม่สามารถเข้าสู่ระบบ (Login) แบบเจ้าหน้าที่ได้<br>- มองไม่เห็นข้อมูลของคนอื่น<br>*(หมายเหตุ: อาจเพิ่มใน Phase หลัง)* |

## 2. ข้อเสนอแนะ Role เพิ่มเติม (Proposed Additional Roles)

**7. System Integration API (Machine-to-Machine)**
- **คำอธิบาย:** ไม่ใช่ผู้ใช้ที่เป็นมนุษย์ แต่เป็น Role สำหรับ "ระบบส่วนกลาง" ที่จะสาดข้อมูล (Sync) เข้ามา
- **เหตุผลที่เสนอ:** จากเอกสาร Requirements ระบุว่าระบบต้องรองรับ *การนำเข้าจากระบบกลาง* ดังนั้น การสร้าง Role หรือ API Token พิเศษสำหรับระบบกลางจะช่วยป้องกันปัญหาคอขวด และทำให้สามารถ Audit ได้ว่าเรื่องร้องเรียนนี้สร้างขึ้นจาก API ไม่ใช่สร้างจากฝีมือเจ้าหน้าที่ศูนย์ดำรงธรรม
- **สิทธิ์ที่ทำได้:** สิทธิ์ในการ `POST` ข้อมูลเรื่องร้องเรียนใหม่เข้าสู่ระบบเท่านั้น

## 3. สรุปความสำคัญ (Key Takeaways for Implementation)
- **Data Segregation:** หัวใจสำคัญที่สุดคือ "หน่วยงานที่รับผิดชอบ" ต้องไม่สามารถมองเห็นเรื่องของหน่วยงานอื่นเด็ดขาด เพื่อป้องกันการละเมิด PDPA
- **State Transition Control:** สิทธิ์การเปลี่ยนสถานะเป็น "ยุติเรื่อง" (Close Case) ถูกสงวนไว้ให้ **ศูนย์ดำรงธรรม** เท่านั้น เพื่อให้มั่นใจว่าศูนย์ดำรงธรรมได้ตรวจสอบความเรียบร้อยของผลการปฏิบัติงานก่อนปิดเคสจริงๆ
