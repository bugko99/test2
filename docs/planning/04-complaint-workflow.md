# Complaint Workflow: ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ (DCMS)
(Project Name: BUGKOShop)

## 1. สถานะของเรื่องร้องเรียนทั้งหมด (Complaint Statuses)
เพื่อการติดตามที่ชัดเจน ระบบจะใช้สถานะ (Status) เหล่านี้เป็นมาตรฐาน:
1. **`NEW` (เรื่องใหม่):** เพิ่งถูกบันทึกเข้าระบบ ยังไม่ผ่านการคัดกรอง
2. **`ASSIGNED` (รอดำเนินการ):** ศูนย์ดำรงธรรมจ่ายเรื่องให้หน่วยงานแล้ว แต่หน่วยงานยังไม่กดรับ
3. **`IN_PROGRESS` (กำลังดำเนินการ):** หน่วยงานกดรับเรื่องและกำลังดำเนินการแก้ไขปัญหา
4. **`PENDING_INFO` (รอข้อมูลเพิ่มเติม):** ติดขัดปัญหา ต้องการข้อมูลจากผู้ร้องเรียนหรือศูนย์ดำรงธรรมเพิ่มเติม
5. **`RESOLVED` (แก้ไขแล้ว):** หน่วยงานรายงานผลการแก้ไขกลับมายังศูนย์ดำรงธรรม
6. **`CLOSED` (ยุติเรื่อง):** ศูนย์ดำรงธรรมตรวจสอบผลและปิดเคสอย่างสมบูรณ์
7. **`REJECTED` (ยกเลิก/ตีตก):** เรื่องร้องเรียนซ้ำซ้อน, ข้อมูลเป็นเท็จ, หรือไม่อยู่ในอำนาจหน้าที่

## 2. Workflow แบบลำดับขั้น (Step-by-Step Workflow)
กระบวนการทำงานหลักตั้งแต่ต้นจนจบ แบ่งเป็น 11 ขั้นตอนดังนี้:

**ขั้นตอนที่ 1: การรับเรื่องร้องเรียน (Complaint Intake)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม / System API (กรณีรับจากระบบกลาง)
- **การกระทำ:** บันทึกข้อมูลเรื่องร้องเรียน ผู้ร้องเรียน และแนบไฟล์หลักฐานเข้าระบบ (สถานะเรื่องคือ `NEW`)

**ขั้นตอนที่ 2: การตรวจสอบข้อมูลเบื้องต้น (Initial Screening)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** ตรวจสอบความถูกต้องของข้อมูล หากเป็นเรื่องซ้ำหรือไม่อยู่ในขอบเขตสามารถตีตกหรือยกเลิก (`REJECTED`) ได้ทันที

**ขั้นตอนที่ 3: การจัดประเภทเรื่องร้องเรียน (Categorization)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** เลือกหมวดหมู่ (เช่น เดือดร้อนรำคาญ, แจ้งเบาะแส, ขอความช่วยเหลือ) เพื่อใช้กำหนด SLA (เวลาที่ต้องดำเนินการให้เสร็จ) พื้นฐาน

**ขั้นตอนที่ 4: การกำหนดพื้นที่หรืออำเภอที่เกี่ยวข้อง (Location Mapping)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** ระบุพื้นที่เกิดเหตุ เพื่อช่วยในการพิจารณาเลือกหน่วยงานหรืออำเภอที่ต้องรับผิดชอบได้แม่นยำขึ้น

**ขั้นตอนที่ 5: การส่งต่อหน่วยงานรับผิดชอบ (Agency Assignment)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** เลือกหน่วยงานที่ต้องแก้ปัญหา และกดปุ่ม "มอบหมายงาน" (สถานะเปลี่ยนเป็น `ASSIGNED`, ระบบเริ่มนับเวลา SLA)

**ขั้นตอนที่ 6: การรับเรื่องโดยหน่วยงาน (Acknowledge)**
- **ผู้รับผิดชอบ:** หน่วยงานที่รับผิดชอบ
- **การกระทำ:** ล็อกอินเข้าระบบและกดปุ่ม "รับเรื่อง" เพื่อยืนยันว่าได้รับทราบปัญหาแล้ว (สถานะเปลี่ยนเป็น `IN_PROGRESS`)

**ขั้นตอนที่ 7: การอัปเดตความคืบหน้า (Progress Update)**
- **ผู้รับผิดชอบ:** หน่วยงานที่รับผิดชอบ
- **การกระทำ:** ระหว่างการแก้ปัญหา หน่วยงานสามารถบันทึกข้อความอัปเดตความคืบหน้าเป็นระยะ เพื่อให้ศูนย์ดำรงธรรมติดตามได้

**ขั้นตอนที่ 8: การขอข้อมูลเพิ่มเติม (Request More Info) - *ถ้ามี***
- **ผู้รับผิดชอบ:** หน่วยงานที่รับผิดชอบ ➔ แจ้งมาที่ เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** หากข้อมูลไม่พอ หน่วยงานสามารถกดขอข้อมูลเพิ่มได้ (สถานะ `PENDING_INFO`) ศูนย์ดำรงธรรมจะติดต่อไปยังผู้ร้อง แล้วนำข้อมูลมาอัปเดตกลับให้หน่วยงาน

**ขั้นตอนที่ 9: การรายงานผลว่าแก้ไขแล้ว (Resolution)**
- **ผู้รับผิดชอบ:** หน่วยงานที่รับผิดชอบ
- **การกระทำ:** เมื่อแก้ปัญหาเสร็จ หน่วยงานจะพิมพ์รายงานผลและแนบหลักฐาน จากนั้นกดปุ่ม "รายงานผลแก้ไขแล้ว" (สถานะเปลี่ยนเป็น `RESOLVED`)

**ขั้นตอนที่ 10: การปิดเรื่อง (Close Case)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม
- **การกระทำ:** ตรวจสอบความเรียบร้อยของผลการปฏิบัติงาน หากผ่านเกณฑ์และสมบูรณ์ ให้กดปุ่ม "ยุติเรื่อง" (สถานะเปลี่ยนเป็น `CLOSED`)

**ขั้นตอนที่ 11: การแจ้งผลให้ประชาชน (Notify Complainant)**
- **ผู้รับผิดชอบ:** เจ้าหน้าที่ศูนย์ดำรงธรรม (หรือระบบทำให้อัตโนมัติหากมีช่องทางดิจิทัล)
- **การกระทำ:** แจ้งผลการแก้ปัญหาให้ประชาชนทราบผ่านช่องทางที่เหมาะสม เช่น โทรศัพท์ หนังสือตอบกลับ หรือแจ้งให้เข้ามาตรวจสอบด้วย Tracking Number

## 3. เงื่อนไขการเปลี่ยนสถานะ (State Transition Control)
เพื่อให้ระบบมีระเบียบ การเปลี่ยนสถานะจะถูกล็อกตามตรรกะดังนี้:
- `NEW` ➔ `ASSIGNED` : ศูนย์ดำรงธรรมมอบหมายงาน
- `NEW` ➔ `REJECTED` : ศูนย์ดำรงธรรมตรวจสอบพบว่าไม่สมควรดำเนินการ (เรื่องซ้ำ/ข้อมูลเท็จ)
- `ASSIGNED` ➔ `IN_PROGRESS` : หน่วยงานกดรับเรื่อง
- `IN_PROGRESS` ➔ `PENDING_INFO` : หน่วยงานต้องการข้อมูลเพิ่มจากผู้ร้อง
- `PENDING_INFO` ➔ `IN_PROGRESS` : ศูนย์ดำรงธรรมให้ข้อมูลเพิ่มกลับไปเรียบร้อยแล้ว
- `IN_PROGRESS` ➔ `RESOLVED` : หน่วยงานแก้ไขปัญหาเสร็จสิ้นและรายงานผล
- `RESOLVED` ➔ `CLOSED` : ศูนย์ดำรงธรรมตรวจสอบและยืนยันการยุติเรื่อง
- `RESOLVED` ➔ `IN_PROGRESS` : ศูนย์ดำรงธรรมตรวจสอบพบว่าการแก้ไขยังไม่สมบูรณ์ ตีเรื่องกลับให้หน่วยงานทำใหม่

## 4. กรณีผิดปกติ (Exception Handling)

| กรณีผิดปกติ | การจัดการในระบบ (Handling Workflow) |
|---|---|
| **ส่งผิดหน่วยงาน (Wrong Assignment)** | หน่วยงานที่ได้รับสามารถกด "ส่งคืน" (Return) พร้อมแจ้งเหตุผลกลับมา ศูนย์ดำรงธรรมจะรับเรื่องกลับ (สถานะคืนสู่ `NEW`) เพื่อพิจารณาส่งให้หน่วยงานที่ถูกต้องใหม่ |
| **เรื่องซ้ำซ้อน (Duplicate)** | ศูนย์ดำรงธรรมสามารถทำเครื่องหมาย "เรื่องซ้ำ" และเชื่อมโยง (Link) ไปยังเรื่องร้องเรียนหลักที่กำลังดำเนินการอยู่ จากนั้นเปลี่ยนสถานะเป็น `REJECTED` หรือควบรวมเรื่อง |
| **ข้อมูลไม่ครบ (Incomplete Info)** | หากตรวจพบตั้งแต่แรก ศูนย์ดำรงธรรมจะค้างสถานะ `NEW` ไว้และตามข้อมูล หากตรวจพบโดยหน่วยงาน จะใช้สถานะ `PENDING_INFO` (สามารถตั้งค่าให้การรอข้อมูลหยุดเวลา SLA ชั่วคราวได้ หากธุรกิจอนุญาต) |
| **เรื่องเกินกำหนด (Overdue/SLA Breach)** | เมื่อเวลาดำเนินการเกิน SLA ระบบจะใส่ Flag หรือสีแจ้งเตือนเป็น "สีแดง" บน Dashboard ทันที หัวหน้าศูนย์ดำรงธรรมจะมีสิทธิ์กด "เร่งรัด" (Expedite) เพื่อส่งการแจ้งเตือนพิเศษไปยังหน่วยงาน |
| **การติดตามเกินกำหนด (Escalation)** | หากเรื่องเกินกำหนดเป็นเวลานาน ระบบสามารถเปิดสถานะแจ้งเตือนไปยังผู้บริหารจังหวัด (ผู้ว่าฯ) อัตโนมัติ เพื่อให้ทราบถึงคอขวดของการดำเนินงาน |
