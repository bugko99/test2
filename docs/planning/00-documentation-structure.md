# Documentation Structure & Strategy

## 1. โครงสร้างโฟลเดอร์ `docs/`
โฟลเดอร์ `docs/` เป็นศูนย์รวมเอกสารทั้งหมดของโปรเจกต์ โดยแบ่งหมวดหมู่หลักดังนี้:
- `docs/planning/`: เอกสารสำหรับการวางแผน การออกแบบระบบ กติกา และ Roadmap
- `docs/testing/`: เอกสารเกี่ยวกับ Test cases, วิธีการทดสอบ และรายงานผลการทดสอบ
- `docs/deployment/`: เอกสารเกี่ยวกับขั้นตอนการนำระบบขึ้นเซิร์ฟเวอร์ (Deploy) และ Environment setup

## 2. โครงสร้าง `docs/planning/`
เป็นที่เก็บไฟล์ทั้งหมดที่เกี่ยวข้องกับการออกแบบก่อนการลงมือเขียนโค้ด การตั้งชื่อจะเรียงตามตัวเลขเพื่อให้เห็นลำดับขั้นตอนที่ชัดเจน ตั้งแต่กติกาการทำงาน ไปจนถึงรายละเอียดทางเทคนิค

## 3. โครงสร้าง `docs/testing/`
จัดเก็บเอกสารสำหรับการทดสอบ เช่น `api-tests.http`, `manual-test-cases.md`, หรือ `acceptance-criteria-checklist.md` สำหรับใช้ประเมินผลระบบ

## 4. โครงสร้าง `docs/deployment/`
จัดเก็บเอกสารคำแนะนำการ Deploy ขึ้นระบบต่างๆ เช่น `railway-deployment-guide.md`, `docker-compose-prod.md`

## 8. กติกาการตั้งชื่อไฟล์
- ใช้ตัวพิมพ์เล็กทั้งหมด (Lowercase)
- ใช้เครื่องหมายขีดกลาง (`-`) แยกคำ (Kebab-case)
- นำหน้าด้วยตัวเลขสองหลัก (เช่น `01-`) เพื่อบังคับลำดับการเรียงไฟล์ให้เป็นระเบียบ (ยกเว้น `PROJECT_CONTEXT.md`)
- ลงท้ายด้วยนามสกุล `.md` เสมอ

## 9. กติกาการเขียน Markdown
- ใช้หัวข้อ (`#`, `##`, `###`) ในการแบ่งหมวดหมู่ให้ชัดเจนและเรียงลำดับอย่างถูกต้อง
- ใช้ **ตัวหนา** สำหรับสิ่งที่ต้องการเน้นย้ำหรือแจ้งเตือน
- ใช้ตาราง (Table) เมื่อต้องการเปรียบเทียบ, อธิบายโครงสร้าง Database, หรือแสดงรายการที่มีโครงสร้างแน่นอน
- ใช้ Code block (` ``` `) สำหรับ Code snippet, โครงสร้าง Folder, หรือตัวอย่าง JSON
- ไฟล์ที่มีขนาดยาวควรมีตารางสารบัญ (Table of Contents)

## 10. วิธีใช้เอกสารเหล่านี้กับ AI ในแต่ละ Phase
- **ก่อนเริ่มโปรเจกต์:** AI จะถูกสั่งให้สร้างไฟล์ตามโครงสร้างนี้ให้ครบถ้วนทีละไฟล์ เพื่อเก็บเป็นฐานความรู้
- **ก่อนเริ่ม Implementation (เขียนโค้ด):** ผู้ใช้ต้องเตือนให้ AI อ่านไฟล์ `PROJECT_CONTEXT.md`, `10-implementation-plan.md` และ `SKILL.md` ทุกครั้ง เพื่อทบทวนเป้าหมาย
- **ระหว่างดำเนินงานใน Phase:** หาก AI หรือผู้ใช้มีข้อสงสัย สามารถอ้างอิงและเปิดอ่านรายละเอียดเจาะจงจากไฟล์ `01` ถึง `09` ได้ตามหมวดหมู่ที่ต้องการ
- **หลังจบ Phase:** AI ต้องรายงานผลตาม Acceptance Criteria ที่ระบุไว้ในแผนงาน และหากมีการแก้ไขโครงสร้างระหว่างทำงาน ต้องเสนอการปรับปรุงเอกสารให้สอดคล้องกันด้วย
